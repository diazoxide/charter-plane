# charter-app's Rust COMPILES on Windows, and that was the surprise of M4

_2026-09-20 20:45 · persistent_

charter-app's Rust COMPILES on Windows, and that was the surprise of M4 (2026 09 20, PR 93). The first windows-latest run ever produced SIX errors in two files, not a wall: forge::is_executable reaching for PermissionsExt with no cfg, and wiring::Lock calling rustix::fs::flock where rustix is a cfg(unix) dependency. Everything else in 63,000 lines of charter-core compiled. With those and charter-cli's six gone, cargo build -p charter-cli finishes in 12.66s and cargo check --workspace --all-targets is down to two errors, both in test targets. nix 0.28 is cfg(unix) so portable-pty is not a blocker, and alacritty_terminal has real cfg(windows) deps and charter only uses its term and grid and vte, never its tty. So the remaining Windows work is NOT the shipped code compiling: it is the containment guards having a Windows expression at all, and the test suite, where stand_in::program is cfg(unix) and 14 of charter-core's 20 integration tests reach for it or for std::os::unix. Lesson for estimating: a platform nobody has compiled on looks infinitely far away and may be six lines away; measure before you cost it.
