charter-app UI tests: never query role="tab" (or any ARIA role the app uses twice) document-wide. Measured 2026-09-18 adding the M1.1 sidebar: the sidebar lists workspaces as a tablist and the session tab strip is another, so App.test.tsx's tabs() helper and e2e/specs/panes.e2e.ts's tabNames() both started mixing a workspace in among the tabs. The e2e failure was baffling — 'Can't call click on element with selector "button=Close tab beta"' — because the spec derives a tab's name from the last [role=tab] it finds and 'beta' is a workspace. Fix is to name each tablist (aria-label="Tabs" on the strip, aria-label="Workspaces" on the sidebar) and scope every query to one, which is right for a screen reader too. Two gotchas: in WebdriverIO the '=text' shorthand is a WHOLE selector and cannot follow a CSS descendant part ('[role=tablist][aria-label=Tabs] [role=tab]=1' is a SyntaxError) — chain it as $('[role=tablist][aria-label=Tabs]').$('[role=tab]=1'); and in Testing Library use within(screen.getByRole('tablist', {name: 'Tabs'})). Expect this again as M1.5 panels and the M1.6 palette land.
