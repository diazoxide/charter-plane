git 2.50.1, measured 2026-09-18 while designing charter-app M1.4. FOUR verified traps for any code driving the git binary. (1) RCE: GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.hooksPath GIT_CONFIG_VALUE_0=<dir> makes 'git -C r worktree add' run <dir>/post-checkout. The GIT_CONFIG* family is config INJECTION, not redirection, and -C does not override it. 'git rev-parse --local-env-vars' prints 15 names; withhold all of them PLUS GIT_CONFIG, GIT_CONFIG_PARAMETERS, GIT_CONFIG_COUNT, and hold the list to that command with a TEST -- Python charter named them by hand in review round 3 and missed GIT_COMMON_DIR in round 4. (2) 'git worktree remove' RESOLVES SYMLINKS in its argument: a symlink at wsA/.worktrees/r/piece -> wsB/victim deletes workspace B's live worktree, exit 0. contain::writable does NOT stop it -- it confines to the plane's data dirs, so another workspace passes. Pass git a resolved, absolute, link-free path. It also falls back to SUFFIX MATCHING for an argument that is not a working tree. (3) 'git check-ref-format --branch' RESOLVES as well as validates: '@{-1}' prints the previous branch name and exits 0. Use the name git PRINTED, never the one you passed. (4) 'git config --get' on a key with two values returns the LAST, exit 0, no warning; overwriting it exits 5. Use --get-all and treat >1 as a refusal, --replace-all to write.
