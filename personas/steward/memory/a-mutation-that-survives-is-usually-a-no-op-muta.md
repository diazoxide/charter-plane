# A mutation that 'survives' is usually a no-op mutation, not an untested

_2026-09-21 00:11 · persistent_

A mutation that 'survives' is usually a no-op mutation, not an untested guard (charter-app M3.1, 2026-09-21). Porting hooks.py's shell lexer to Rust, 34 one-rule mutations were run against the Python oracle; four of the first batch changed no answer, and in every case the mutation was wrong rather than the test weak. Two examples worth keeping: (1) reordering the redirections ahead of the control operators in _OPERATOR_SPLIT_RE is PROVABLY inert - no control operator is a prefix of any redirection, since every redirection starts < or > - so what actually keeps 'cat 2>&1 <vault>' in one segment is that '>&' is IN the table and precedes '>', not the group order the docstring credits; (2) mutating Python's is_python_space to c.isspace() is a no-op because CPython's isspace() already counts U+001C-U+001F - the real divergence is Rust's char::is_whitespace, which does not. Before concluding 'this rule has no test', first prove the mutation changes behaviour at all. The one genuine gap the round DID find was real: split_punctuation's per-piece offsets were compared by nothing, because lex reports pre-split tokens and segments are text only - and those offsets are exactly what A7 reads.
