_2026-09-22 13:33 · persistent_

charter-app layout storage ruling (M6.3, PR #149, 2026-09-22): the window's region arrangement is kept in localStorage under 'charter.layout', NOT in the machine store (ADR 0034/0040) and NOT in a file beside machine.json like the theme (charter-app#144). The deciding argument is the first frame: both of those are read over an asynchronous Tauri command, and a theme can afford that because a built-in is compiled into the bundle and applied before React renders — a layout has no stand-in, the operator's arrangement IS the thing, so reading it after the first paint means painting the default and re-laying-out, which is exactly the flash the ticket removed. Web storage is the only store a webview answers synchronously. Secondary argument: ADR 0040 amended 0034 for 'how the operator arranged what this file already names', and a region arrangement names nothing the machine store holds, so 0034 is not amended again. If a layout ever has to be shared, hand-edited or plugin-contributed (ADR 0041), the file route has to INJECT it at window creation rather than be fetched from the window.
