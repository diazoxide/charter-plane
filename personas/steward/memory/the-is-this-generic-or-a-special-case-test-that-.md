# The test for whether a charter feature is generic or a special case: i

_2026-09-25 · persistent_

The test for whether a charter feature is generic or a special case: it is generic if it adds a ROW, not a COLUMN, meaning one entry in a table charter already owns, with no new verb, flag or concept. Named vendor integrations (op://, vault://, a keyring provider) pass that test, so 'vendor-agnostic' is the wrong bar. Settled two issues on 2026-08-19: reading a browser session token became one secret-resolver row (browser://<session>/localstorage/<key>) instead of a new subcommand, and every consuming path then worked untouched. Ask 'row or column?' before designing any new charter surface.
