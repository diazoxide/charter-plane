charter-app on Windows (M4, 2026-09-20, PR 93, issues 95-102): portable-pty 0.9's INTERFACE is clean — session.rs uses only openpty/try_clone_reader/take_writer/CommandBuilder/spawn_command/resize, so nothing unix-only leaks into the Engine trait. ConPTY breaks three SEMANTIC properties instead: (1) drop(pair.slave) closes nothing because the slave is an Arc clone of the master's Inner and the pipe's write end belongs to the pseudo console, so the reader never sees EOF and when_it_ends never fires — the end must come from a wait on the child handle; (2) WinChild::is_complete reads STILL_ACTIVE (259) as 'not finished', so a program exiting 259 never exits, and a failed GetExitCodeProcess also reports 'running'; (3) CreateProcessW is used with no job object, so kill() is TerminateProcess on one handle and every descendant survives — the process-group equivalent is a job object with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE. Also: dropping a master is ClosePseudoConsole, which BLOCKS while a client is still attached, so charter must never drop one on the UI thread. nix 0.28 is #![cfg(unix)] so portable-pty's unconditional nix dep compiles to nothing on Windows and is not a blocker.
