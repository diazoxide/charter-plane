_2026-09-25 · persistent_

Vault/leak guard false-positive shape (Python CLI, fixed PR #266; the rule carries into charter-app's leak guard): a reader program (cat, less, head, tail, grep, rg, awk, sed, od, xxd, strings, bat...) was denied whenever ANY argument mentioned .charter/(vaults/|browser|active-) — including a heredoc body fed to the reader, a sed/awk script, or a grep pattern — so documentation that merely mentions charter's layout was refused as a read. Correct shape: strip heredoc bodies only when fed to a reader (a body fed to bash/python is a script and must stay visible), and match only real FILE operands, skipping script/pattern operands and flag values. The flag-takes-a-value table must be per tool ('head -n 5' takes a count, 'sed -n' takes nothing), or a shared table swallows sed's script operand and lets 'sed -n 1p .charter/active-persona' through. A bare '.charter/vaults' with no trailing slash is deliberately unmatched so the registry file .charter/vaults.json stays readable.
