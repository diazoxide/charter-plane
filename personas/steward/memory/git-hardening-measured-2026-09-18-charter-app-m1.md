_2026-09-18 19:17 · persistent_

git hardening, measured 2026-09-18 (charter-app M1.4). env_clear() is NOT enough to make a git subprocess safe, because HOME has to stay. git reads its global config from HOME and that config NAMES PROGRAMS: with exactly HOME+PATH+GIT_TERMINAL_PROMPT+LC_ALL and nothing else, an attacker-set HOME ran core.hooksPath on 'worktree add' and core.fsmonitor on 'status'. HOME cannot be dropped (global config + every credential helper live there). Fix: pin the keys on the COMMAND LINE, '-c core.hooksPath=/dev/null -c core.fsmonitor=false' -- -c beats every config file. Residual: credential.helper and core.sshCommand, which push needs and cannot blanket-disable. ALSO: after env_clear, Command::new("git") resolves against the CHILD's PATH, so a bare name plus a fixed PATH list silently breaks every machine whose git is elsewhere (NixOS, asdf/mise, ~/.local/bin) -- resolve the binary in the PARENT and pass an absolute path. ALSO: never canonicalize the directory you are using as a containment ANCHOR: canonicalize follows a link AT that name, so a committed symlink there moves the boundary with the attack.
