Two mutation-testing rules, learned the hard way on #1113 (exit-gate task 2, 2026-09-16). (1) A test stub that answers the SAME row/choice on every call turns a deleted guard into a CI HANG rather than a red test: the loop under test keeps being handed a valid answer forever. Make a stub answer once and then raise. One such stub cancelled a whole 14-shard sweep run after a 67-minute hang, and the shards read as 'failed' when they were cancelled. (2) An equivalent mutant CANNOT be pinned, and a test written to look like it pins one is worse than leaving the survivor: it reads as coverage forever. Measure both arms over every possible input first; if they answer the same, delete the line and, where the code around it has a real property, assert THAT instead (on #1113: a respawn carries the five identity names and nothing else, #446). Also measured there: a budget/syscall test that primes OUTSIDE its mock.patch block compares a cold measurement against a warm one, so which side pays depends on module ordering and adding unrelated tests can hide the regression — prime again INSIDE the patches.
