# A ? on a per-line parse inside a loop abandons the whole document

_2026-09-20 21:30 · persistent_

charter-app#67 (2026-09-20): a ? on a per-line parse inside a Rust for loop abandons the WHOLE document on one bad line, where the Python reader continues. personas::frontmatter_value did exactly that and lost a persona role whenever anything above role: was not a key: value line. Swept every for/while body in charter-core and charter-cli for the same shape: nothing else. The other ten sites are deliberate and already say so (forge::to_query refuses the whole command for one unbuildable block, as Python does; glrefresh per-character digit parse; scaffold and doctor::git propagating real IO/git errors; the rest are ? inside a closure, where it skips the item). The fix was to DELETE the third reader rather than patch it: personas::frontmatter is already persona._frontmatter line for line and news::frontmatter already calls it, so role() now shares it and collapses with meta(), which is dict(pairs) - last line wins. Two silent divergences went with it: the opening fence was matched on a TRIMMED line (charter tests text.startswith), and the first role: line won where the charter dict keeps the last.
