_2026-09-23 04:24 · persistent_

A SWEEP-style change (the same attribute added to every element of a kind) collides SILENTLY with every branch written before it, and only a property test catches it. Measured 2026-09-23 on charter-app: #190 added tabIndex={0} to every <button> in every modal, because WebKit leaves a button out of the tab sequence unless its tabindex is written down. Two branches then merged against it, both CLEANLY, both typechecking: in DeleteWorkspace the result was fine; in NewProject it was NOT - #197 had added a second directory picker AFTER the sweep, so that button carried no tabIndex of its own, and the merged dialog could not be finished by keyboard (the walk reached Folder, Browse, Repository-to-adopt and then stopped, never reaching the checkbox, Create project or Cancel). Nothing in git, tsc, eslint or reading the diff could see it; Modals.keyboard.test.tsx went red. THE RULE: when a sweep lands, every in-flight branch that ADDS an element of the swept kind is a silent regression waiting to merge - grep the merged file for elements of that kind lacking the attribute, and never satisfy the property test by updating its expected list, because the list is the property. Corollary for briefs: a sweep should land with a test that enumerates the swept kind, not one that enumerates today's instances.
