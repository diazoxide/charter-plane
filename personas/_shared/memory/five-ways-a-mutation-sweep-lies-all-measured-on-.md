Five ways a mutation run lies (measured 2026-08-26/27). Four produce a FALSE PIN (says tested when it is not): (1) exit-code scoring: deleting a refusal left the exit code unchanged because a later check caught the same input, so score on the SET of newly failing test ids, not the rc; (2) a broken baseline: a copied tree that errors some tests in every run makes every mutation look pinned, so assert a GREEN baseline and difference it away; (3) stale build caches: Python's .pyc is validated on source size and whole-second mtime, so two same-length mutants written in one second ran each other's bytecode; with cargo, make sure the mutant is actually rebuilt (fingerprints, sccache) and prove it from inside the run; (4) a mutation that HANGS is no verdict: it needs a timeout reported as its own outcome (UNRESOLVED), not folded into either column. The fifth produces a FALSE SURVIVOR: (5) a mutation whose edit never applied (the match string did not match) runs an unmutated tree and reports the guard unpinned. Every mutation must assert that it actually applied.
