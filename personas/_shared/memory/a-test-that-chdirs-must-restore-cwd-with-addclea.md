A test that changes process-global state (cwd, env vars, umask) must restore it, and a leak shows up as failures in unrelated tests that look like a platform or toolchain split. On charter #823 a leaked cwd (restored in the wrong cleanup order, so the case ended inside a directory about to be deleted) produced ~40 errors across nine unrelated modules. I read the check-runs as 'fails on two interpreter versions, passes on two' and diagnosed a language difference. Wrong: every version failed, and the split I saw was a run still in flight. Two rules: (1) a CI split with no other version signal is more likely leaked process state than a toolchain difference, so check what the failing tests share with the run's order first; in Rust, cwd and env are process-global and cargo runs tests on parallel threads, so a test that sets them races every other test in the binary; (2) never diagnose from a CI snapshot that has not finished.
