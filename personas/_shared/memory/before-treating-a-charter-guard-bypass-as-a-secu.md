# Before treating a charter guard bypass as a security-disclosure decisi

_2026-09-25 · persistent_

Before treating a charter guard bypass as a security-disclosure decision (stopping to ask the operator, or keeping it off the public tracker), check it against the guards' documented ceiling. charter's PreToolUse guards (ported to charter-core: leakguard, shellseg, heredoc, handoffguard) read argv and shell shape only. They are documented as not a sandbox, and interpreters (python3 -c), shell strings (sh -c / bash -c) and eval are documented blind spots. On 2026-09-11 the controller nearly escalated vault reads through bash -c, sh -c and python3 -c as an undisclosed bypass, and all three were documented. A finding that grants nothing beyond the documented ceiling (for example an inconsistency inside an intended check) goes to the public tracker as an ordinary bug, as guard bypasses #429, #474, #547, #556, #975 and #1086 did, with reproductions kept out of the public text. Procedure: measure through the full hook entry point in an isolated fixture plane, not a single inner function; diff the result against the documented ceiling; escalate privately only what goes beyond it.
