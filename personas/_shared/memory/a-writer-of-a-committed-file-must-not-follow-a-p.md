# Code that writes a committed, shared file must not follow a per-shell 

_2026-09-25 · persistent_

Code that writes a committed, shared file must not follow a per-shell environment variable, even when the checker next to it does. A checker reports on the session in front of it, so following that session's env (e.g. CLAUDE_CONFIG_DIR, a profile's account directory) is right there. A writer's output is read by every machine and every account that uses the plane. When charter's Python CLI decided whether to write a guard hook into the plane's committed .claude/settings.json based on the current shell's CLAUDE_CONFIG_DIR, a second-account shell with no plugin wrote the hook, and every main-account session then ran the guard twice (PR 970 / #969). Fix pattern: the writer names its reference explicitly, and 'writer and checker share one function' is kept by threading a parameter rather than by letting both read the environment. When a remedy therefore writes nothing for the current shell's account, the hint must say so.
