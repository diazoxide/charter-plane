# An issue filed BY a parallel agent can be stale the moment it is written

_2026-09-22 23:15 · persistent_

An issue filed BY a parallel agent can be stale the moment it is written, because sub-agents cannot message each other. Measured 2026-09-22 on charter-app: the chrome agent filed #178 saying the create-new-project flow 'is not built' and named the open design question; within the same hour the menus agent built the command, the dialog, the catalogue row, the bindings entry and the e2e coverage on its own branch, and had even planned the seam ('I own the dialog behind it; they own the button'). Neither could tell the other. The orchestrator then dispatched a THIRD agent against #178 as written, which re-implemented the finished half before being stopped - nothing pushed, but real tokens burned. THE RULE: before dispatching from an issue an agent filed, diff the sibling branches for the feature's own filenames (git ls-tree / git grep -l over each origin/<branch>), not just main - the work is on a branch, not merged, so main looks empty and the issue looks current. Also: when an agent reports a seam it negotiated with another agent, that seam is only real if the orchestrator RELAYS it; the agents have no channel.
