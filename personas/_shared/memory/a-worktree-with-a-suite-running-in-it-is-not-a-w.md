# While a test suite runs in a tree, that tree is frozen: no rebase, no 

_2026-09-25 · persistent_

While a test suite runs in a tree, that tree is frozen: no rebase, no checkout, no hand-applied mutation, no revert. Doing any of these produces false signals in either direction. On charter #857 a test that read its own module's source from disk at run time (inspect.getsource on an already-imported module) raised IndexError because the author rebased the worktree onto a base that touched that file while the suite was live. The failure was evidence of nothing about the branch or about main. The tell is any test that reads source or fixture text from disk at run time instead of exercising behaviour. It reports on whatever the tree became, not what it was. In charter-app that includes Rust tests that read files at run time (not include_str!, which is fixed at compile time) and e2e specs that load fixtures. It also includes cargo rebuilding under you if you touch sources between runs. If you need to keep working while a suite runs, use a second worktree.
