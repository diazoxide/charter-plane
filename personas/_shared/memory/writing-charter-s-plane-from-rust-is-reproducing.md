# Writing charter's plane from Rust is reproducing CPython's json/str form

_2026-09-18 01:06 · persistent_

Writing charter's plane from Rust is reproducing CPython's json/str formatting, not serialising a struct — verified 2026-09-18 in charter-app M1.1 by running both sides. Three divergences, each of which silently corrupts a stable file: (1) json.dumps defaults to ensure_ascii=True, so an em-dash is '\u2014'; serde_json emits it literally. (2) json.dumps(sort_keys=True) separators are ', ' and ': '; serde_json packs them. (3) json.dumps spells control chars \n \t \r \b \f in shorthand and everything else below 0x20 as \u00XX; a naive escaper writes \u000a. Why it matters: workspace.json's charter_generated is sha256 over json.dumps(doc-minus-that-key, sort_keys=True), so ANY of the three flips the file's ownership from 'charter' to 'operator', and charter's automatic writers then leave it alone forever — a silent stop, not an error. Separately, Python's str.splitlines() (used by workspace.py's _replace_md_section) breaks on \v \f \x1c \x1d \x1e \x85 U+2028 U+2029; Rust's lines() breaks on none of them, so a '## Header' after one of those stops being a section boundary. charter-core has pyjson.rs and mdsection.rs reproducing all of this, proven against the committed fixture planes.
