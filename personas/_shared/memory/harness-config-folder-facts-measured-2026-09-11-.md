# Harness config-folder facts, measured 2026-09-11 on claude 2.1.268, co

_2026-09-25 · persistent_

Harness config-folder facts, measured 2026-09-11 on claude 2.1.268, codex-cli 0.147.0 and opencode 1.18.23 in throwaway folders with no login. (1) Claude Code: CLAUDE_CONFIG_DIR moves the login (the Keychain service becomes 'Claude Code-credentials-<sha256(dir)[:8]>'), and plugins whose marketplace is declared only in ~/.claude/settings.json are absent there even when project settings enable them. The binary also reads CLAUDE_SECURESTORAGE_CONFIG_DIR, which by its code moves only the login (not measured at runtime). (2) Codex: CODEX_HOME moves config.toml, auth.json, the plugin cache and hook trust; 'codex plugin list' cannot tell an empty home from a wired one; its default shell_environment_policy passed an inherited *_TOKEN variable through. (3) opencode: the login is XDG_DATA_HOME/opencode/auth.json, plugins are XDG_CONFIG_HOME/opencode/plugin, and it also reads ~/.opencode/ regardless; moving XDG_CONFIG_HOME also logs gh out. (4) 'claude plugin list --json' writes .claude.json and backups/ into whichever config folder it runs against, so any check that calls it is not write-free.
