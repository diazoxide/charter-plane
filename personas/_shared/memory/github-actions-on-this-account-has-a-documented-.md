# GitHub Actions on this account has a documented ceiling of 20 CONCURRENT

_2026-09-22 23:07 · persistent_

GitHub Actions on this account has a documented ceiling of 20 CONCURRENT JOBS, shared across diazoxide/charter-plane AND diazoxide/charter (written down in charter's .github/workflows/sweep.yml:42 and test.yml:10). This is the binding constraint on CI wall clock whenever more than one run is in flight, and it is why a run can sit 'pending' with ZERO jobs allocated for minutes - GitHub holds the whole run before handing out runners, and gh pr checks then prints 'no checks reported on the branch', which looks like a broken workflow and is not. Practical consequences, measured 2026-09-22: (1) sharding a job reduces the CRITICAL PATH (charter-app main went 31m to 11m after #177 split the differential six ways) but raises how many of the 20 slots one run wants at once, from ~12 to ~17, so several PRs in flight queue against each other harder; (2) charter's own 'Size the sweep' plus its shards can occupy most of the ceiling on their own, so a charter-app PR can be blocked by work in the OTHER repo; (3) once a long serial job is sharded, the next lever is FEWER JOBS PER RUN, not more sharding.
