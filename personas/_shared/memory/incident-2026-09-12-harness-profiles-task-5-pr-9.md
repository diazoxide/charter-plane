INCIDENT 2026-09-12: the operator's live chat was closed and its session lost while three implementer agents ran in parallel. Two mechanisms, both ours. (1) A cleanup path ran a destructive 'close this window' command whose target fell back to an inherited environment variable on the operator's REAL server; an agent answering a mutation survivor had deleted the if-no-target guard, and the tests stripped that variable, so the call ran with an empty target, which the tool read as 'the current one', i.e. the operator's chat. Rule: a destructive command acts only on a target proven to be this process's own (by pid or recorded id), never falls back to the environment or a default instance, never passes an empty target. A mutation survivor that is a SAFETY guard gets a test, never a deletion. (2) Agents ran pkill -f on a shared test command repeatedly, killing each other's and other sessions' runs; several deaths reported as memory pressure were this. Never kill by pattern; stop only a PID you started.
