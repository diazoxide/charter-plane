A script that edits source by string replacement MUST assert, because a no-op replace is silent and reports success. Hit 2026-09-22 resolving charter-app merge conflicts: a python helper put each branch's commands back into main's reindented collect_commands! block by anchoring on '            doctor::plane_doctor,' - main had changed that block's indentation, so str.replace matched nothing, returned the string unchanged, and the script printed the list of commands it believed it had inserted. Three Tauri commands vanished from the list. bindings.ts was then REGENERATED from that list, so the generated file was faithfully wrong, and the whole thing was internally consistent: commands still defined in workspaces.rs, still called from the TSX, only the registration list missing them. tsc caught it ('Module bindings has no exported member AtRisk'), nothing else would have. TWO RULES: (1) every replace in an edit script gets 'assert anchor in s' before and a count assertion after - 'assert s.count(x) == 1' - never a bare .replace(); (2) regenerating a generated file does not validate it, it only makes it agree with a source that may itself be broken - the typechecker is the only thing that reads both sides.
