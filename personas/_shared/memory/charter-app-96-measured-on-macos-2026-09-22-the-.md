charter-app#96, measured on macOS 2026-09-22: the name alphabets and contain::segment_ok BOTH accept names that resolve elsewhere on Windows, and this is LIVE on macOS rather than a Windows port item. segment_ok returns true for nul, NUL, con, com1.txt, aux, lpt9, 'alpha.', alpha:evil and PROGRA~1; workspace_name_ok('nul'), persona_name_ok('nul') and workspace_name_ok('alpha.') are all true, so the alphabet catches neither device names nor a trailing dot. alpha:evil IS caught by the alphabet, so it is reachable only through the segment_ok-only callers - session ids, memory ids, clone names, worktree names, inventory. WHY IT IS LIVE: contain.rs's own SEPARATORS doctrine is that a plane is COMMITTED AND TRAVELS, so a macOS charter mints these into a plane, commits them, and hands them to a machine that resolves them somewhere else. The defect is created on the machine that cannot see it. Same threat model as charter#442. The general lesson for any cross-platform naming gate: 'this platform does not care' is not a reason to accept a name, because the artefact travels - gate at MINT time, never at read time, or you lock someone out of a plane they already have.
