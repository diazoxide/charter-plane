# An agent started inside a charter chat inherits that chat's environmen

_2026-09-25 · persistent_

An agent started inside a charter chat inherits that chat's environment (CHARTER_* variables such as the session id, workspace and hook socket, plus anything the harness sets). So any reproduction of 'no session' or 'outside charter' behaviour is silently invalid unless you clear that state first. Found 2026-08-31 on #764: the author tested that nine commands print nothing outside a session, and the repro ran the in-session path the whole time. Both paths print nothing, so the invalid repro produced the expected output and looked like confirmation. Rule: before reproducing session-absent behaviour, clear the inherited state explicitly (env -u for each CHARTER_* variable; check `env | grep -i charter`) and assert the cleared state at the top of the repro. Do not assume a fresh shell is fresh. The matching discipline on the other side: isolate your test's state (HOME, config dirs, sockets) so it cannot see the operator's live app.
