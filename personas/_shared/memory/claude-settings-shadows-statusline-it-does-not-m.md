claude --settings SHADOWS statusLine, it does not merge it (measured 2026-09-22, Claude Code 2.1.280, macOS, real pty, fenced HOME). --settings merges with settings already in force at the KEY level, but statusLine is one key and the flag is the last writer: with a statusLine in ~/.claude/settings.json AND one in the --settings flag, ONLY the flag's runs - the file's command is never invoked at all, with no warning, no error and no chain. A control launch proved the file's statusLine was valid and would otherwise have fired. So any app that arms statusLine through --settings silently replaces whatever statusLine its operator configured. Three more measured facts about the statusLine command: (1) it is EVENT-DRIVEN, not timed - one invocation at startup, zero over ~30s idle, one more per submitted turn, so polling its output file between turns reads nothing new; (2) the whole payload arrives on STDIN, argv is empty; (3) context_window is present but current_usage/used_percentage/remaining_percentage are all JSON null on a fresh session with no usage - that is every chat's normal first render, and null is not the same value as absent, so test both. used_percentage counts cache reads toward used (total_input_tokens = input + cache_creation + cache_read) and current_usage breaks cache_read_input_tokens and cache_creation_input_tokens out separately. Values are computed from the transcript's last assistant usage, not from a live connection.
